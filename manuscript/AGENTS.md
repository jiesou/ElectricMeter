## 语言风格（重要）

- 仿照现有的语言风格
- **简短** 干净利落清晰。不要说狗屁废话，不要反复重复
- **简短、简短、简短** 新加的都应该是一句话两句话，不要废话一二三
- 语言要正式，不是表演舞台剧，不要做作不要夸张
- 语言要正式，说话像人，不加比喻不加语法。**严禁** 句式“……不是……而是”、“……就像……”、“你可能有疑惑……”、“始终秉持这样一个理念……”

## 文档性质
这是一份**职教类大赛的项目汇报演示脚本**（项目名：电气柜装接调试上岗培训平台）。
- 形式：**多人角色剧本**，角色代号：蒋（硬件/总协调）、吴（AI 工程师）、何（嵌入式开发）、韩（电路设计）。
- 大量**删除线 `~~...~~`** 内容 = 已废弃/不念的台词（如 362-369 行整段素养旧稿、53/166/167/267 等行内删除）。
- 大量**圆括号 `（...）`** 内容 = 舞台提示/导演备注（如站位、评委遗忘提醒、待补数据），不属于念词。

## 修改约定（重要）
1. **不要删除 `~~删除线~~` 与 `（）` 备注**。它们是作者留的修订痕迹，下次还要用。
2. **占位符补全**：`XX`/`xxxx`/`***Ω` 等保留即可，不要臆造技术参数（如射频阻抗值、阻值）。
3. 改稿时按上文「全文逐节概要」的小节定位，先确认要动的是哪一节再动。

## 常用操作
- 拉最新原文（只有这个能拿到可读文字）：`kdocs-cli drive read-file --args '{"url":"https://www.kdocs.cn/l/crtJBLjj5Fqx"}' --output markdown > ./full.md`
- 如果读文档是为了理解内容， 那就完整更新 full.md，然后读 full.md 本身即可，读 JSON 太费劲
- 读文档结构/段落的 JSON 精确格式（不易读文字）用 `kdocs-cli wps read-text --file '{"url":...,"action":"full_content"}'`
- 逐段编辑用 `wps.write-text` 的 `paragraph_update`（按 `paragraph_index`，从 1 开始）或 `wps.search-replace` 的 `replace`。`read-file` 导出有缓存，写完必须用 `wps.read-text full_content` 独立回读验证，不能只信返回的 `code:0`。
- 替换的 `find_text` 要字节级精确匹配文档真实内容：先 `range_content`/`full_content` 抓出真实串再回传，不要凭记忆手敲（多余空格或不可见字符会让匹配失败却仍返回 `code:0` 假成功）。含换行/长文本时 `search_replace` 不稳，按段落 `paragraph_update` 整段覆盖更可靠。
- 大段写入用脚本生成 JSON `--file` 传入，禁止对话里贴 Base64/长文。
