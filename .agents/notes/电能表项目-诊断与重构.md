# 电能表智能能源管理项目：诊断与重构

> 对象：既有项目"利用智能电能表做云平台能源管理"（统计用电量 / AI / 绿色 / 人走断电 / 无卡取电 / 超功率报警 / 独居老人异常关怀）
> 任务：判断它能不能做世校赛选题；若能，怎么补掉两个缺口
> 关联文档：[`选题头脑风暴-岗位群对接.md`](选题头脑风暴-岗位群对接.md)、[`选题头脑风暴-弱电机柜方向.md`](选题头脑风暴-弱电机柜方向.md)、[`选题头脑风暴-新维度发散.md`](选题头脑风暴-新维度发散.md)

---

## 1. 先明确：这个项目的家底有多厚

逐条对评分表点数：

| 评分维度 | 权重 | 这个项目的现有资产 | 判断 |
|---|:--:|---|---|
| 技能水平 | 60% | 电表通信接入、协议解析、云端平台、移动端、AI 应用 | **骨架齐全**（但见 §2 缺口） |
| 职业素养 | 10% | 用电安全天然自带规范叙事（接线规范、线缆整齐、数据隐私） | 强 |
| **应用价值** | 10% | **独居老人关怀 = 全场稀缺的民生落点**；绿色低碳是政策强叙事 | **极强，别丢** |
| 团队合作 | 10% | 端/边/云/移动 四层天然可分四工位 | 强 |
| 创新创意 | 10% | 用**电表数据反推人的行为**，这个"数据复用"本身就是创新点 | 强 |

**核心判断：这个项目的短板不是"应用价值"，而恰恰是"技能水平"里的一环。**

## 2. 真问题：闭环缺了最后一环 —— "现场处置"

赛道要求的闭环是 **数据采集 → 研判分析 → 任务调度 → 现场处置**。逐环对照：

| 环节 | 现有项目 | 状态 |
|---|---|---|
| 数据采集 | 智能电表联网上报 | ✅ 强 |
| 研判分析 | 统计、AI、超功率报警、老人异常识别 | ✅ 强 |
| 任务调度 | 工单派发 / 移动端推送（若有） | ⚠️ 纸面 |
| **现场处置** | **？** | ❌ **空** |

**这一环是致命的**，原因有三个：
1. **60 分钟展演没有"可做的动作"**——除接线和敲代码外，全程在看大屏。评委看不到"手上功夫"，技能水平 60% 拿不满。
2. **电表是"只看得见、动不了"的装置**——报警响了，然后呢？没有"然后"，就没有故事高潮。
3. **装置体量撑不起来**——几块电表 + 一台电脑，占不了地方。

### 补法：给项目加"手和脚"

| 补什么 | 怎么补 | 补上后出现什么动作 |
|---|---|---|
| **可控开关** | 智能断路器 / 磁保持继电器 / 接触器模块，受云平台指令驱动 | 报警 → **真的拉闸** → 大屏功率曲线瞬间归零 |
| **真负载台架** | 自建计量插座（PZEM-004T / ESP32 自制）+ 真实负载（电水壶、电暖器、电动车充电模拟） | 现场**真的插上电水壶**，系统真的识别出来 |
| **多路分区** | 配电箱式面板，分 4~6 路，每路独立计量 + 独立通断 | 分区控制、负载转移、越限切除 |
| **声光/门禁联动** | 存在感应 + 声光报警器 + 门禁 | "人走断电"变成**人一离开、灯真的灭** |
| **移动端处置** | 真机 App 收工单 → 到场核验 → 扫码闭环 | 第 1 类岗位群（移动开发）从配角变主角 |

> **补完之后，60 分钟里评委至少能看到 5 个"物理动作"**：插真负载被识别 / 超功率被拉闸 / 人走灯灭 / 电动车充电被判定违规并限流 / 老人异常触发网格员派单。
> 这些动作全部是**不可预演的真实现场行为**，正是"任务难易度"和"操作熟练度"的证据。

## 3. 伪问题一："没有区域特色" —— 可解，而且宁波的切口很好

原始项目之所以"没区域特色"，是因为它停在**家庭**这个最没有地域性的抽象层。往上走一层就有了：

| 宁波切口 | 真实痛点（有政府文件、有事故、有考核压力） | 与电表能力的关系 |
|---|---|---|
| **出租房 / 群租房电气安全** | 宁波城中村、产业工人聚集区群租房，**违规使用大功率电器、电动车入户充电**是电气火灾主因；消防与流管部门有专项整治与数字化监管要求 | **直接命中**：分区计量 + 负载辨识 + 远程限流 |
| **老旧小区改造 / 未来社区** | 浙江"未来社区"建设是省级硬任务，老旧小区电力容量不足 + 独居老人比例高 | 容量治理 + 老人关怀 |
| **慈溪/余姚家庭作坊与小微园区** | 前店后厂、住产混用，用电安全与消防风险高，业主无人管电 | 分区监测 + 安全告警 + 电费分摊 |
| **酒店 / 长租公寓 / 人才公寓** | 宁波文旅与产业园区配套；"**无卡取电**"在这里是真实商用功能 | 人走断电 + 无卡取电 + 分户计费 |
| 海岛山区县（象山、宁海） | 留守老人多，网格员覆盖半径大 | 独居老人关怀（这条线的**最佳落地土壤**） |

**推荐主切口：出租房 / 群租房电气安全 + 电费治理**——因为它同时是"民生痛点"和"企业/政府生产问题"。

## 4. 伪问题二："不是生产问题" —— 三层破解

### 4.1 先纠正一个事实

评分表里"应用价值"的原文是：能否切实解决行业企业**生产经营或民生服务**中的实际困难。
→ **"民生服务"是被明文承认的。** 你现在的担忧，本质是怕评委"感觉不够硬"，而不是规则不允许。

**佐证**：调研报告里两个金奖/银奖项目本身就是民生向——成都石化工业学校的《智慧校园数字孪生》（真实校园能耗治理）、低空巡检（林区防飞）。

### 4.2 但评委的"感觉"确实重要 —— 所以换成 B 端甲方视角讲

家庭端最要命的不是"不是生产问题"，而是**"谁付钱？"答不上来**。换成有付费主体的讲法，生产性立刻出现：

| 甲方 | 他为什么付钱 | 可量化的"提效" |
|---|---|---|
| **长租公寓 / 二房东 / 物业** | 人工抄表、催缴、欠费、纠纷成本高 | 抄表人工 **100% 归零**；欠费率下降；电费纠纷工单减少 |
| **小微园区 / 家庭作坊业主** | 火灾风险与安全责任，无人管电 | 隐患从"事后追责"变"事前拦截"；保险与合规风险下降 |
| **酒店 / 公寓运营方** | 空置房间空调照明空耗 | 空置能耗下降，**人走断电 + 无卡取电**直接折算电费 |
| **养老服务机构 / 社区网格** | 独居老人看护人力成本极高 | 关怀从"人力巡查"变"异常触发派单"，**人力成本可量化下降** |
| **工厂 / 商业建筑** | 需量电费、峰谷价差 | 需量削峰、需求响应收益 |
| **虚拟电厂 / 售电公司** | 聚合可调负荷参与电网交易 | 聚合容量×响应收益，**纯信息技术商业模式** |

> 关键话术转变：把"我们做了一个家庭用电 App"改成
> **"我们为 XX 运营方交付了一套电费与用电安全托管服务，人工抄表归零、违规用电实时拦截、独居老人异常自动派单。"**

### 4.3 最强的一步：把电表变成"企业生产设备"

有一个切口可以让这个项目**彻底变成生产问题**，而且技术上是同一个内核：

> **小微企业"能效 + 安全"托管服务**：面向慈溪/余姚家庭作坊、小微园区，用同一套电表 + 边缘网关，
> 同时交付 **①分路计量与电费分摊 ②设备能效诊断与异常停机预警 ③电气火灾隐患拦截**。
>
> **"提效"就有了明确指标**：非计划停机减少 X 小时/月、单位产品电耗下降 Y%、安全巡检人工减少 Z 人天。
> 而养老关怀则是**同一平台上"民生服务"的第二个业务面**——一套技术，两个甲方，应用价值直接拉满。

## 5. 技术王牌：NILM —— 让这个项目从"抄表"升级为"看懂"

原项目最容易被评为"不就是个远程抄表吗"。破解靠一个技术点：

### 非侵入式负荷辨识（NILM）+ 电器指纹

**核心洞察：电表能看到的，远不止"用了多少度电"。**

| 从电力数据里能读出什么 | 用什么方法 | 对应哪个业务 |
|---|---|---|
| **哪些电器在运行** | 功率阶跃特征、启停时间、爬坡曲线、谐波特征 | 违规大功率电器识别、电动车充电识别 |
| **电器的健康状态** | 稳态功率漂移、启动电流异常、运行时长偏离 | 设备劣化预警（生产场景） |
| **人在不在家、在做什么** | 用电行为的时序模式与日常基线对比 | **独居老人异常关怀** |
| **电气安全隐患** | 剩余电流、电弧特征、谐波畸变、中性线电流 | 电气火灾预警（安全场景） |

**这一招的杀伤力在于"一次采集、三处复用"**：
```
        智能电表 + 自制计量插座（高频采集）
                    ↓
            边缘侧 NILM 负荷辨识
                    ↓
   ┌────────────────┼────────────────┐
   ↓                ↓                ↓
用电安全          能效诊断         行为关怀
(电动车上楼/       (设备劣化/       (独居老人
 大功率违规/       电费分摊/        生活异常)
 电气火灾)         需量削峰)
```
→ 第 4 类岗位群（数据采集/处理/分析/标注）从"画曲线"变成"**做特征工程与标注**"，
→ 第 3 类岗位群（安全）有了真实载体，
→ 第 1 类岗位群（移动端）成为处置闭环的入口，
→ 第 2、6 类岗位群靠**配电箱接线 + 边缘网关调试 + 通信链路**承接。

### 硬件上的关键取舍（建议）

- **不要只买成品智能电表**——它只给你总功率一个数，看不出电器。
- **自制"智能计量插座/分路模块"**：PZEM-004T（或类似计量芯片）+ ESP32/STM32 + 继电器，
  单路成本极低，可做 6~8 路。**这正好是"自制硬件"能力的展示**，也解决了装置体量问题。
- 成品电表保留 1~2 只做**真实电网侧计量**（证明方案能对接真实现场，不是玩具）。

## 6. 装置设计：从"几块电表"到"一面配电墙"

```
┌──────────────── 大屏：能效 / 安全 / 关怀 三视图切换 ────────────────┐
│                                                                    │
│  [A 区 模拟配电箱]        [B 区 19" 机柜]        [C 区 处置席]      │
│  1 只真实智能电表（总）    边缘网关/NILM 推理     平板 + 真机 App    │
│  6~8 路自制计量插座        K8s/信创服务器         运维工单/派单      │
│  智能断路器（可控通断）     EMQX/MQTT + 时序库     声光报警器        │
│  真实负载：电水壶/电暖器    Redis + MySQL          存在感应传感器    │
│  电动车充电模拟 / 阻性负载  防火墙+准入(安全侧)     扫码核验闭环      │
└────────────────────────────────────────────────────────────────────┘
```
- **体量**：配电墙（约 1.2 m 面板）+ 19" 机柜 + 处置席 ≈ **2.5~3 m 宽**，占地成立。
- **动手动作**：接线/端子排/线槽绑扎（第 2 类）＋ 网关与网络调试（第 6 类）＋ 抓包与准入（第 3 类）。
- **强电安全**：全部走 **24V/安全电压 + 隔离电源 + 漏保**，负载用低功率模拟件，避免评委对"现场用电"的顾虑。

## 7. 60 分钟脚本骨架（动静交织）

| 时段 | 动作 | 岗位群 |
|---|---|---|
| 0–5 min | 破题：从"抄表"到"读懂用电行为"；亮出三视图与量化指标 | 主讲 |
| 5–15 min | **施工**：配电箱分路接线、计量模块端接、线槽绑扎、上电校验 | 2、6 |
| 15–25 min | **接入**：网关配置、MQTT 上报、时序库落库、大屏三视图点亮 | 6、4 |
| 25–35 min | **研判**：现场插入真负载（电水壶/电暖器）→ NILM 识别 → 基线与异常判定 | 4 |
| 35–45 min | **处置**：超功率 → 自动限流/拉闸（曲线归零）；人走 → 灯灭；电动车充电 → 判定违规并告警；异常触发工单派单 | 1、3 |
| 45–55 min | **安全加固**：抓包/准入策略/未授权设备隔离；数据脱敏与隐私合规说明 | 3、6 |
| 55–60 min | **价值验收**：抄表人工归零、隐患拦截数、关怀派单时效、节能与收益测算 | 主讲、5 |

## 9. 结论与待办

**结论：项目保留，做三件事升级——**
1. **补"现场处置"闭环**：加可控通断 + 真负载 + 移动端派单。（这是决定成败的一步）
2. **换甲方视角**：从"家庭 App"改为"出租房/小微园区用电安全与电费托管服务"。
3. **加技术王牌**：NILM 负荷辨识，让"抄表"变成"看懂用电行为"，一招三用（安全 / 能效 / 关怀）。

**唯一需提前确认的合规项**：用电数据涉及个人行为，必须讲清**数据最小化与脱敏**（只上报异常事件、原始数据不出边缘），
这既是风险规避，也能反过来变成第 3 类岗位群的加分点。
