# 统计页与角色切换：端到端验收记录

> 性质：agent 产出的一次实跑记录，供复用。

## 环境

- server `bun run start`（:8080），web `bun run dev`（:5174，5173 被占）。
- 下位机：**真机** `48aff3`（房名「301真机」，192.168.11.174）经 `/ws` 接入并持续上报；没跑 simulator。

## 验过的

| 项 | 怎么验 | 结果 |
|---|---|---|
| 真机接入与账本 | `/api/entities/48aff3/*` + 库里的 `EntityHistory` | 三只表按各自毫秒 ts 落行，`energyKwh` 是服务器侧累计值 |
| 拨天 | 页头「进入下一天」×2 | `/api/stats` 的 `now` 前进 2 天，「在住 · 第 3 天」跟着变 |

| 入住 / 退房 | 统计页点「办理入住」「办理退房」 | 在住状态与 `occupied` 同步；退房后记录表新增一行 |

## 数出来的数

- 样本剂量：`SEED_DAYS = 30`、每分钟一个采样点，一块表一次入住约 120~600 行；18 块表 30 天约 33 万行（本次只有一间房，32,913 行）。
- 一次入住 5~29 kWh，日均 5~14 kWh。
- 查询：一次入住 = 每块表两次「某时刻的值」（走主键），按天/按小时再各问一次，不扫区间。

## 验收之后又改了什么

一轮 `find-code-simplifications` 只读审查（子代理）报的问题，值得改的都改了：删掉没人读的 `StatsRoom.end_ts`、`data.ts` 的 mock 分支与 `refresh/pullStats` 合成一种写法、幽灵柱颜色收进 `--primary-ghost` 主题令牌、`stats.ts` 立 `Bill` 接口并把缓存键改名、`energy.ts` 参数名去掉下划线、`history.test.ts` 的自引用断言改 `toMatchObject`；另外修了一处审查没提但确有的不一致 —— **统计页设备横条的颜色原来按用量排名取，跟客房页按实体 id 序取的回路配色对不上**，现在两边都按 id 序。改完 `bun test` 64 pass、`web check`/`build` 与 `server tsc` 全过。

**顺带修掉一个 flake**：`history.test.ts` 里「累计电量只增不减」原来断言绝对累计值，而 `energy.ts` 的基线会在 import 时从账本最新一行接上（设计要的行为）——bun 并行跑测试文件时，别的文件可能已经往同一个测试库写过同一间房的行，基线被垫高，这条就偶发失败（12 次单文件跑里复现 1~2 次）。改成断言**差值**（才是它要证的东西），单文件跑 12 次、全量跑 5 次都不再复现。

## 已知不足

- 演示里本次入住只有当前这一小时的真实数据，所以它的 24 小时区间图基本一根柱；有形状的是历史样本。
- bench 上的真机没接负载，`powerW` 一直是 0，所以实跑出来的账单是 0 kWh（验完已把这条测试账单删掉，库里留的是 30 条样本）。
- 演示样本的房名取自接入的真实房间，删房会连带清掉它的样本与账单（外键级联）。
