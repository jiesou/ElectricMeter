# 房间管理

## 三个动作落哪

| 动作 | 谁做 |
|---|---|
| 新建客房 | **不用接口**。设备连上 `/ws` 时 `hub.connect()` 已经 upsert 建房，房名先拿 `device_id` 顶 |
| 改房名 | `PATCH /api/rooms/:device_id`，body `{ name: string }` |
| 删客房 | `DELETE /api/rooms/:device_id` |

两个接口都在 `server/routes/rooms.ts`，跟客房快照放在一起。

## 谁算一间房

只看 id：**除 `bigscreen`（大屏只替别的房报人数）之外，每台设备都是房**，报没报过实体都算。判据是 `core/util.ts` 的 `isRoom`，`/api/rooms` 的 `snapshot()` 与 `core/stats.ts` 的 `report()` 都用它，前端与别处不再做任何排除。

## 改房名

内存和库**都要写**：只写库的话，下一帧 `/api/rooms` 读的还是内存里那个旧名；只写内存的话重启就丢。

改完再给那台设备推一条 `pub_name`：下位机屏幕顶上显示的就是这个名字，改完屏上立刻跟着变，固件里不写死房号。

`hub.connect()` 重连时只 `update: { ip }`，不碰 `name`，所以设备重连不会把改过的名字冲掉。

房名去掉首尾空白后为空、或者不是字符串，都返回 400。

## 删客房

`hub.devices.delete(id)` 加 `db.device.delete({ id })`。

`EntityHistory` 外键指向 `Entity`、`Entity` 外键指向 `Device`，两级都是 `onDelete: Cascade`，SQLite 的 `foreign_keys` 也是开的，所以删设备会连着实体的历史读数一起清掉，不用另写清理逻辑。

设备要是还连着 WS，删掉之后下一帧快照它会自己重新建回来。这是接受的，没有做黑名单去挡。

## 验收

`server/routes/rooms.test.ts` 覆盖：改名同时落到快照和库、改名推给设备、设备重连不冲掉改过的名、删房清掉设备与实体与历史、未知客房和空房名被挡下。
