## 为什么这个文档存在？

**因为网页要能被"照着文档重新写一遍"而不走样——文档定的是那些不能猜的东西（配色、导航形态、尺寸下限、库选型），不定实现细节。**

## 要怎么改文档

- 只写"不定下来每次写出来都不一样"的东西
- 能引用别的文档就不复述

### 别再犯

1. **写太细 → 437 行**，塞满算法推导、ASCII 图、实施步骤。子代理被噪音淹没。
2. **写太简 → 49 行**，什么都没定，子代理自由发挥，直接照抄 SlintUI 变成深色 + 顶部 tab 栏。
3. **过度执行"学谁"**。我写"大屏是唯一观感来源"，子代理就复刻了它的皮。正确表述是：**只借信息结构，不借皮**。

### 改文档的三条规矩

1. **只定"不能猜"的**：配色令牌、导航形态（桌面左栏 200px / 窄屏底部 tab 64px）、小卡最小 180px、功率表不小于 140px、曲线三档高度。
2. **别人的内容只引用不复述**。曲线→`历史记录与统计.md`，mock→`Mock模式.md`，改名/删房→`房间管理.md`。

## 要什么

打开网页就是客房管理页面。

网页是一个**桌面管理后台**，跑在电脑、平板、手机上。它跟大屏是同一套业务的两种终端，不是同一套界面。

## 跟大屏什么关系

大屏 `slintui/` 是**香橙派上那块嵌入式屏**，深色、大字号、远距离看、只有触摸。网页是**管理后台**，浅色、有鼠标。

## 长什么样

整体沿用浅色卡片风，不另起炉灶。

### 配色

颜色只在 `styles.css` 的 `:root` 定义，组件和图表一律 `var(...)` 取用，**任何地方都不写死颜色**：

```css
--bg:#f8fafc          --card:#ffffff        --text:#0f172a        --muted:#475569
--primary:#1d4ed8     --primary-soft:#eff6ff
--green:#15803d       --green-soft:#f0fdf4
--gray-soft:#f1f5f9   --warn:#92400e        --warn-soft:#fffbeb
--border:#e2e8f0      --radius:12px         --shadow:0 1px 2px rgb(15 23 42 / 0.25)
/* 回路配色：一条回路一个颜色 */
--circuit-1:#f87171   --circuit-2:#4ade80   --circuit-3:#facc15
```

**默认色统一**：电表和开关**默认都是 `--primary`**（弧线、通电底色），别一个蓝一个绿。房级总表 / 总闸就吃这个默认色。

**回路配色**：一个回路（开关 + 它的电表 + 它在曲线里的那条线）共用一个颜色。取色板 **400 档**（red / green / yellow）——三色亮度一致才协调，也比 600 档柔和；**不用蓝**，蓝留给默认色，不然分不清「这条回路的色」和「默认色」。

对应关系靠 entity id 认——**电表 id 就是开关 id 加 `-meter`**（`light` ↔ `light-meter`），`color.ts` 里 `circuitIndex()` 按开关在实体表里的顺序编号，组件挂 `--circuit` 变量，Chart.js 那边用 `circuitColor()` 从主题读出真颜色值。

页面底色 `--bg`，卡片底色 `--card`，卡片描边 `1px solid var(--border)`，圆角 `--radius`。**不用深色底，不做大面积渐变、毛玻璃、重阴影。**

### 导航

- **≥ 1024px（桌面）**：左侧固定竖栏，宽 200px，`background: var(--card)`，右边框 `1px solid var(--border)`。竖排导航项。每项高 44px、圆角 10px，选中项用 `--primary` 文字 + `--primary-soft` 底色。
- **< 1024px（平板、手机）**：左侧栏隐藏，改成**底部固定 tab 栏**，高 64px，`background: var(--card)`，上边框 `1px solid var(--border)`，另外留 `env(safe-area-inset-bottom)`。两个 tab 等分宽度，图标在上文字在下，图标 22px、文字 14px，选中项同样用 `--primary` + `--primary-soft`。

导航：

- 房子图标 **客房管理**（`/rooms`）
- 摄像头图标 **视频监控**（`/camera`）

### 页头与字号

网页顶部固定加粗居中的大标题「民宿智能用电管理系统」，右侧放一个连接状态标签。

字号：页标题 24px、房名 20px、关键读数 20–32px、正文 16px、辅助信息 13–14px。数字统一等宽数字（`font-variant-numeric: tabular-nums`）。

字体用系统字体，不外链字体。

## 客房管理

打开网页就是客房管理页面，一间房一张大卡片，卡片里直接铺着这间房的电表和开关。

每间房的卡片，放在一起，形成客房管理页面。

### 顶部

页头下面一行放搜索框。

### 客房卡片

一张房卡从上到下四块：房头、房级行、曲线、Entity 区。

**房头一行**，垂直居中：

1. 在线圆点，直径 10px。在线 `--green`，离线 `--muted` 且 `opacity: .5`。
2. 房名，20px、加粗，可换行。房名可以**点一下就地改**，回车提交、Esc 取消。
3. 「在线」/「离线」文字，14px、`--muted`。

**房级行**：这间房自己的总表和总闸，横跨房卡、高 140px，在曲线正上方。左边是**房级总表**（功率表边长 120px + 下面一行 13px 的累计 kWh，靠左），右边是**竖总闸**，两者与下面的曲线左右对齐。

**功率曲线一条**，详见下面「曲线图」。

**Entity 区**：电表和开关各排一格，详见下面「Entity 小卡」。

离线房整体 `opacity: .72`，数值照样显示（那是最后上报值）。

房卡右上角放一个删除图标，点了先二次确认再删。

### Entity 小卡

电表和开关都是**宽度自适应的方格小卡**，用 `grid` 排，一格一个。

**小卡的最小宽度定 180px，别再小。**

```css
grid-template-columns: repeat(auto-fill, minmax(180px, 1fr));
gap: 12px;
```

理由：功率表是个正方形，它要缩到小卡的内容宽度里。小卡 140px 时内容区只剩 116px，弧半径跌到 44px，刻度线只有 8px，指针和数字全糊在一起，读不出来。180px 时内容区 156px，弧半径 59px，刻度 11px，才看得清。

**小卡内容区最小 156px，功率表跟着这个宽度走，但不小于 140px。** 写成一层 `min-width` 兜底：小卡内容宽度小于 140px 时，功率表就停在 140px 不再缩，宁可小卡内部出现一点点横向留白，也不让表缩到不可读。

**电表小卡**：竖排、居中，名字（14px、`--muted`，缺名字用Entity  id）→ 功率表（正方形，边长 = 内容宽度）→ 「累计 12.40 kWh」（13px、`--muted`、居中）。卡片 `background: var(--card)`、`1px solid var(--border)`、圆角 10px、内边距 12px。

**开关小卡**：一台闸一张卡，卡宽 120px、竖排。名字在上（14px、`--muted`，缺名字用 Entity id）→ 竖闸体（48×76px，圆角 24px；开为 `--green` 系、关为灰系，圆点 40px 从下往上走 68px，带 200ms 的 `ease-out`）。**名字是闸上唯一的文字**，开关状态看圆点位置就知道，不写「通电」「断开」。整卡可点，点一下切本地状态；离线房不可点，未上报时整体 `opacity: .5`。

**整房总闸**：闸体大一号（56×88px、圆点 46px），在房级行右侧。状态取全房所有开关Entity 的聚合——**全部** 为 on 才显示 on。点一下把所有开关一起切到相反值。

## 示数

功率和电量各有各的写法，收在 `web/src/format.ts` 里，房级总表、电表小卡、功率表里的数字都走它，不在组件里各写各的。

**功率**：1000 W 以下写整数瓦 `0 W`、`320 W`；1000 W 起进位到千瓦、保留一位小数 `1.2 kW`。

**电量**：固定两位小数 `0.00 kWh`。

**没上报**：数字位置写 `—`，不写 0。

## 曲线图

房卡内一条，堆叠面积图，能看出灯、热水壶、吹风机各占多少。

**用 Chart.js 画**，Vue 侧包一层 `vue-chartjs`。按需注册，只引折线、填充、tooltip 和坐标轴这几样，别 `import "chart.js/auto"`。

**尺寸**：宽度撑满房卡，**高度按档位固定**，不跟着宽度变：

| 视口 | 高度 |
|---|---|
| < 640px | 130px |
| 640–1023px | 150px |
| ≥ 1024px | 170px |

Chart.js 默认按容器尺寸自适应（`responsive: true` + `maintainAspectRatio: false`），高度交给上面这个档位，宽度跟着房卡走，不用自己算缩放。房卡变宽，同一时间窗里的点距自动拉开。

**堆叠**：每个电表一个 dataset，`fill: 'stack'`，坐标轴 `stacked: true`，就是自下而上堆起来的效果。颜色走回路配色（见上），填充半透明、描边实色。

**悬停**：开内置 tooltip，`mode: 'index'` + `intersect: false`，鼠标落在哪个时刻就列出该时刻所有电表的读数（名字 + 功率），末行是合计。时间标签写成 `HH:MM:SS` 本地时间 —— **只有这里用时间格式，数据层一律 number 秒级时间戳**。

图的观感要收着点，别用 Chart.js 的默认皮：关掉动画或压到很短（每秒来一帧，动画会互相追），去掉图例，网格线调淡，tooltip 白底细边框，字体跟着页面的字号走。

边界：还没有历史点时显示「正在加载曲线」；只有 1 个点显示「数据积累中」；历史接口失败就静默不画，**不影响房卡其余部分**；这间房没有电表就整块不渲染。

## 边界

- **开关只画不接**。整房开关和每个 Entity 的开关都只是界面，点一下只切本地状态，不发请求，刷新就回到接口的值。服务器现在没有向下位机下发的通道，等 action 系统做了再接。
- 不新建客房：设备接入时后端自己建，见[房间管理](房间管理.md)。
- 不做告警、登录。
- 不引组件库。曲线用 Chart.js，功率表手写 SVG，别的不引。
- 不改 `shared/types.ts`。

## 验收

- 一切宽度都不出现横向滚动，360px 可用、1440px 内容居中限宽。
- 深色一点都没有：页面底色、卡片底色、导航都是上面那套浅色令牌。
- 桌面是左侧竖栏，窄屏是底部 tab，和旧 WebUI 一致；不是顶部深色横栏。
- 功率表在小卡最窄时也读得清：弧、刻度、指针、数字不重叠。
- 曲线是堆叠的，能看出每个电表各占多少；鼠标悬停有 tooltip，列出该时刻各电表读数和合计，合计等于各读数之和。
- 曲线宽度跟着房卡变，高度停在对应档位，不被压扁或拔高。
- 房级行的表与闸、以及下面的曲线，左右两边对齐。
- 闸上除名字外没有文字，闸的开合只看圆点位置。
- 功率与电量的写法在房级总表、电表小卡、功率表里一致。
- 六种情形（正常 / 零功率 / 离线 / 无Entity  / 多Entity  / 长名称读数未齐）都不崩、不塌、不叠字。
- `bun run --cwd web check` 与 `build` 通过。
