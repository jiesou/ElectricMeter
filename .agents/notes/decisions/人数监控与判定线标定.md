# 人数监控与判定线标定

## 定论

- 一台摄像头看**多个门**（走廊广角）→ 一个机位一组判定线，**一条判定线绑一间客房**。
- 挂靠用 **`device_id`**（服务器侧「客房」就是一台 ESP32 device），不用房间名字符串。
- 判定线**继续由 OpenCV 画进帧**（跟人框同路），不搬到 Slint。
- 人数监控页 = 左画面 + 右栏（**上：每间房一行 进 / 出 / 净；下：控件区**）。
- 控件区四样：**标定 / 图传开关 / 换摄像头 / 清零**。
- 标定是**这一页的第二个形态**，不新增 tab、不新增页面文件。
- 这轮只跑**当前机位**，多路并行推理等上板实测。

## 数据（settings.json）

```json
"cameras": [
  { "device": "/dev/video0",
    "rooms": [
      { "device_id": "esp-301", "line": [[0.35, 0], [0.35, 1]] },
      { "device_id": "esp-302", "line": [[0.68, 0], [0.68, 1]] }
    ] }
]
```

- 顶层 `line` 退休；`video`（离线视频源）保留。
- `device` 用 `/dev/videoN` **路径**不用序号 —— camera_service 会按 USB 物理端口去重再按分辨率排序，序号会变。
- **没线的房间就是「未标定」**，不会自动长出一条线。
- 老 `settings.json` 里只有顶层 `line` 时读到空即可，**不写迁移代码**，重新标一次。

## 计数语义（人进屋后消失怎么办）

判据只有一条：同一个 track **上一帧的 side 符号 × 这一帧的 side 符号 < 0**。

- 人进门后从画面里消失 → track 被清 → **不产生任何计数**。这是对的，不去补。
- 人出门时是**全新 track id**（旧 id 早过期）。新 id 第一次只记 side、不计数，所以他从屋内一侧跨到走廊照样算 `out` —— **id 连不连续不影响判定**，判的是「跨线」不是「认人」。
- **明确否掉**：不要拿「人消失了」当「人进屋了」的判据。走廊尽头、柱子遮挡、漏检一帧都算消失，用它确认归属必然误判。
- 死区 ε = 画面高 **2%**：中心点落在死区里算「线上」，不改变侧别 —— 治人在门口站着、身体中心在线上下抖导致的反复进出。
- 漏计的唯一来源是**跨线那一刻被门板/门框挡掉**。靠标定解决：**线往走廊侧挪一点**，让人完整可见地走完跨线动作。
- 口径老老实实是「进 / 出 / 净」，不假装是真实人数。

## 多条线怎么算

- **1 个 tracker + N 个 `LineCounter`**，一份 tracks 喂所有线，各自维护 `sides` 与累计。
- 两条线互不干扰的前提：各自贴着自己那扇门、垂直于人的行进方向。人在 301 门前路过，走的是平行于线的方向，不跨线。
- **`set_line` 必须清 `sides`**，否则换线瞬间所有 track 的旧侧符号一比对，会凭空刷出一堆假进出。
- 线按索引给不同颜色，一屏几根黄线分不清谁是谁。

## 页面与控件

| 控件 | 行为 | 实现 |
| --- | --- | --- |
| ⚙ 标定 | 进标定态 | `calibration.py` |
| ⇪ 图传 | 开/关推给服务器的 UDP 图传 | `pipeline.send = sender if 开 else None` |
| ⇄ 换摄像头 | 画面、判定线组、计数一起换 | 换 `read_frame` + `counters` + 清 tracker/counter 状态，**不重启线程** |
| 清零 | 进/出归零 | 演示要能「再走一遍」，否则只能重启 |

- 图传开关默认按 `settings.json` 里 `image_feed_udp_url` **有没有值**决定，开关状态**不落盘**。关掉时服务器 `/api/cv/stream` 停在最后一帧，这是预期。
- 换摄像头只有一个机位时置灰。切过去 = 旧机位停、新机位跑，**没在看的机位不计数**。
- 设置页那行「图传地址」保留只读展示，实际开关在人数监控页。

## 标定

- 标定态：全屏画面 + 各条线的把手与房号标签 + 侧栏房间列表 + 新增 / 删除线 + 完成。
- 拖动链路：`TouchArea.pressed` → **Python 命中测试**（点到端点 / 点到线段）→ `moved` 读 `mouse-x/mouse-y` → 立刻 `set_line`。几何全在 Python 用 numpy 算，`.slint` 里不写数学。
- 拖动中每帧 `set_line` 都会清 `sides` → 标定期间不计数，正合期望。
- 线仍由 OpenCV 画进帧，拖动会滞后一帧 → **标定态把 `pipeline.fps` 从 10 提到 20**（50ms，基本无感）；**把手由 Slint 即时画**，视觉焦点在把手上。
- **不额外加一条 Slint 的线**，避免两套画法、两条线打架。
- **「完成」才 `settings.sync()`** —— 拖动中只改内存，不每秒往 SD 卡写几十次盘。不点完成就重启 = 回旧线。

## 文件

- **`camera.py`** —— 人数监控页的门面：把 pipeline 的帧推给 UI（含把手/房号标签坐标）、图传开关、换摄像头、清零、`bind_camera(window, ...)`。`main.py` 里的 `build_pipeline()` 挪进来，main 只剩装配。
- **`calibration.py`** —— 判定线标定：`cameras[]` 的线数据读写、命中测试、拖动、新增/删除、完成落盘。
- 依赖单向：`camera.py` 每帧调一次 `calibration` 刷把手和标签，反过来不调。

## 怎么落

### 类与文件

```python
# vision/counter.py
LINE_COLORS = [(0, 215, 255), (0, 255, 140), (255, 130, 0), (200, 0, 255)]
DEAD_ZONE = 0.02                    # 画面高的 2%

class LineCounter:
    def __init__(self, p1, p2, device_id="", index=0)
    def set_line(self, p1, p2)      # 换线 + 清 sides
    def reset(self)                 # 进 / 出归零
    def update(self, tracks, shape) # 死区里 continue：不更新也不清除侧别
    def draw(self, frame)           # 颜色按 index
```

`LineCounter` 自己带 `device_id` —— **线就是这间房的线，不再另造一份线数据再同步**。

```python
# vision/pipeline.py
Pipeline(read_frame, detector, tracker, counters=(), send=None, fps=10)
# counter → counters；self.counts 去掉，要计数直接读 counter.in_count；fps 每轮现读，运行时能改
```

```python
# calibration.py —— 一台机位的判定线
class Calibration:
    def __init__(self, device)      # 从 settings 读这台机位的线 → 建 counters
    counters                        # [LineCounter]，同时也是 pipeline 的 counters
    def press(self, x, y)           # 归一化坐标；命中（端点优先）→ 选中 + 记 grab 偏移
    def drag(self, x, y)            # 按模式算新线 → counter.set_line
    def release(self)
    def add(self, device_id)        # 加一条 DEFAULT_LINE
    def remove(self)                # 删选中的那条
    def save(self)                  # 写回 settings.json + sync
```

- 几何：端点用**平方距离**，线身用 `|cross| / |P2-P1|`。x / y 归一化到不同像素尺度，算距离时 x 要乘画面宽高比。
- 命中优先端点、其次线身，阈值按画面短边折像素。

```python
# camera.py —— 人数监控页
class CameraPage:
    def __init__(self, power_stream)  # 建 pipeline / sender / 当前机位 / Calibration
    def start(self)
    def bind(self, window)            # 帧推送 + 房间行 + 控件 + 标定态
```

- 帧来源决定 `device` 标识：`video` 有值就是视频文件路径，否则 `/dev/video0`。**离线和真摄像头不共用线**（画面不一样，本来就不该共用）。
- 帧推送（16ms）：`latest_frame` → `Image.load_from_array`；标定态另推每条线的房号标签坐标。
- 房间行：`power_stream` 的房间 join `Calibration.counters`，**内容变了才重建**（Slint struct 只能 UI 线程造，每秒造 60 次没必要）。
- 进标定态把 `pipeline.fps` 提到 20，退出回 10。

### ui/

- `camera-viewport.slint`：暴露画面在组件里的实际矩形（`image-fit: contain` 的黑边要减掉，`draw-w` / `draw-h` / `view-x` / `view-y`），手指坐标与把手坐标都靠它换算 —— **不换算判定线就会飘**。
- `people-page.slint`：struct（`RoomRow` / `LineLabel`）、global `PeoplePageData`、右栏与标定叠加层都在这一个文件里。**`.slint` 里没有组件时没法被单独加载，Python 就构造不了它的 struct** —— 所以原来单独的 `people-page-data.slint` 并了进来（`power-page.slint` 本来就是这么放的）。
- 右栏上 = 房间行（**必须包在 `ScrollView` 里**）、下 = 控件区；标定态右栏换侧栏（房间列表 + 删除 + 完成），画面上叠把手与房号标签。
  - 真机有 19 台设备，行一溢出控件就被挤出可视区、连点都点不到。设备名形如 `esp-101`，名字列要留够宽（104px），不然被裁成 `esp-10`。
- `settings-page.slint`：判定线那行改成「在人数监控页标定」。

### Slint 坑（踩过了）

- `Math.` 命名空间**不存在**，是顶层 `min / max / abs / sqrt / pow`。
- 函数要在属性绑定里用，必须 `public pure function`；只写 `public function` 会被当 impure 报错。
- `image` 属性有 `.width` / `.height`（源图尺寸）。
- `TouchArea` 的按下 / 抬起用 `pointer-event(e)` + `e.kind == PointerEventKind.down / up`，移动用 `moved` + `mouse-x` / `mouse-y`。

## 本机验收（2026-02 已跑过）

- **计数回归**：`DEAD_ZONE = 0` 时 `run_video.py samples/vtest.avi --line 0.35,0.1,0.35,0.95` 跑出 **17 / 11 / 6**，与重构前 `samples/counts.csv` 的 `17,11,6` 逐字一致 —— 说明 `set_line` / 多 counter / pipeline 改动零行为变化。开死区（2%）后是 **13 / 8 / 5**：压掉的 7 次就是贴线抖动。**这个差值是死区的代价与收益，调 `DEAD_ZONE` 即可权衡。**
- **死区语义**：中心点落在带子里就 `continue`（不更新也不清除侧别），所以「在死区里第一次出现、随后走向另一侧」的那一次跨线**不算**。换来的是贴线抖动绝不多算；实测抖动 `±1%` 来回不计数 ✓。
- **标定几何**（无窗口单测）：点线身 / 点端点命中并选中、拖端点只动一端、拖线身两点同平移、按下偏移保留（不跳）、增删后 index 重排、`save()` 写回的 JSON 结构、重新读回一致、标签落点 —— 全过。
- **CameraPage**（无窗口单测）：帧来源选路、四条线的载入、图传开关（`pipeline.send` 真的变 None / 变回来）、清零、进标定态提帧率到 20 / 完成回 10、未标定房间点一下加线并选中、已标定房间点一下只选中、删线、`labels` 与把手坐标推送 —— 全过。
- **像素验收**（截图逐像素量）：判定线画在 x=527..531，与归一化 0.35 换算出来的 529 一致；标定态里**紫把手正好压在线的端点上**（同一列 x）、房号标签贴在线旁 —— 说明 `image-fit: contain` 的黑边换算是对的。
- **踩到的两个真机坑（已修）**：真服务器有 **19 台设备**，客房行一溢出就把控件行挤出可视区（点都点不到）→ 行列表包进 `ScrollView`；设备名形如 `esp-101`，名字列 76px 被裁成 `esp-10` → 放宽到 104px。
- **没能验的**：这个沙箱里窗口可见面比布局小（1920x1080 的布局只露出左上 850x687），**合成点击 / 按键送不到 app**（点右上角 X 都不退出，与 [slintui/AGENTS.md](../../../slintui/AGENTS.md) 里「合成按键要焦点」的限制一致）。所以**「手指按下 → 选中 → 拖动 → 落盘」这条交互链路只验到几何与渲染，没做真触摸实测**，上板时手点一次。
