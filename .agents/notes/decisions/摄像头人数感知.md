# 摄像头人数感知

## 定论

- 大屏这一轮**只做「人数 + 摄像头画面」**，历史曲线 / SSE 事件流 / 通断 / 语音 / 数字孪生都往后放。
- Slint UI 由 **Python 驱动**，Rust 只做叙事与薄层（见 [SlintUI-Rust与Python分工.md](./SlintUI-Rust与Python分工.md)）。
- 检测模型 **YOLO11n**，只取 COCO 的 person 类；**双后端**：本机 ONNX（onnxruntime）、板子 RKNN（rknnlite）。两条路共用一个 `Detector`，按模型后缀自动选。
- 模型文件（都不入库，`slintui/models/` 已 gitignore）：
  - `yolo11n.onnx` —— 自己导，单输出 `[1, 84, 8400]`（`slintui/scripts/export_yolo11n.py`）
  - `yolo11n.rknn` —— 直接拿老仓库 `Playground/ElectricDriveCVClient/ultralytics_yolo11/yolo11n.rknn`，9 输出改过头，DFL 在 Python 侧算
- **不用线程池**：老仓库的 `rknnpool.py` 定义了但无人调用，新项目也不引入；抓帧一条线程 + 推理一条线程就够。
- 跟踪：自写 **ByteTracker**（贪心 IoU 两阶段：高分先配、低分补配续命），比老仓库多给一个 track id 与中心点——跨线计数要靠 id 认人。
- 计数：**判定线**（归一化两点，跟分辨率无关），轨迹中心跨线判方向，累计 `in / out / 净`。多条线、一线一客房、怎么标定见 [人数监控与判定线标定.md](./人数监控与判定线标定.md)。
- 画面：**框与判定线由 OpenCV 画进帧**，再 `slint.Image.load_from_array` 送 UI；**文字一律走 Slint 原生 Text**，不画进画面。
- 素材用**公开测试视频/图片**（本机没有摄像头，板子上才接真头）。

## 端口统一 8080

一个 TCP 8080（Bun 服务器：REST / `/ws` / MJPEG）+ 一个 UDP 8080（收大屏推来的图传）。没有额外进程、没有额外端口。

## 大屏界面（照老板端的壳）

底部 tab 栏 + 整页内容，三页：

- **客房用电** —— 轮询服务器 REST（`/api/devices` + `/api/entities`），一张表：客房 / 状态 / 功率 / 电量 / 回路
- **人数监控** —— 左边画面（框和判定线由 OpenCV 画），右边上：每间房一行 进 / 出 / 净，下：标定 / 图传 / 换摄像头 / 清零
- **设置** —— 服务器地址可改并保存（写 `settings.json`，重启生效），模型 / 视频源 / 判定线 / 图传地址只读展示；判定线在人数监控页进标定态调

页头是「左上大标题 + 渐变下划线」，右上三个圆角胶囊按钮（换摄像头 / 明暗 / 退出），跟老板端一致。

## 两个 Slint 坑（都踩过了）

- **Slint 的 struct 只能在 UI 线程构造**：在轮询线程里造 `RoomRow` 会直接崩（`PyStruct is unsendable, but sent to another thread`）。后台线程只攒纯数据，UI 线程的 Timer 回调里再转 struct。
- **struct 构造必须用关键字参数**：`RoomRow(a, b, c, ...)` 位置参数不报错但字段全空，`RoomRow(name=..., ...)` 才正常。

## 本机验收

- 检测 + 跟踪 + 跨线：`slintui/run_video.py` 跑公开视频，出 `samples/annotated.mp4`（带框录像）与 `samples/counts.csv`（逐帧 in/out/now）。
- 两种头解出来的框逐一对齐（IoU 1.00）：我们自己导的标准头 ONNX 与老仓库改头 ONNX 结果一致。
- UDP 图传：`slintui/check_udp.py` —— 裸 socket 核对包头（47/47 分片、最大包 1472B、重组 68423B），再发给服务器、从 `http://127.0.0.1:8080/api/cv/stream` 取回，与最后发出的一帧平均像素差 2.36（同帧，JPEG 有损）。
- 大屏实发也验过：跑 `main.py` 时从服务器 MJPEG 取回的那一帧，**就是带绿框和判定线的标注帧**（绿框像素 0.96%、黄线 1.18%）。

## 还没做的

- **板端 RKNN 与真摄像头没上板实测**：本机只能保证前后处理与解码一致。
- **板端 aarch64：发送端的 `frame_sender` 现在编的是本机 x86_64 的 `.so`**，上板要用 maturin 在板上重编（或 cross 交叉编译）。收图在服务器侧，与架构无关。
- 真实 WiFi 的丢包/乱序没压过（现在都是本机回环；协议本身容忍乱序、缺片丢整帧）。
- 老 Python 的 `slintui/udp_frame_uploader.py` 已被 Rust 模块取代，成了死代码。
