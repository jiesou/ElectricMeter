# 网页前端第二版设计：介绍页 + 3D 沙盘孪生 + 管理页换肤

## 1. 定论

用户已确认：采用融合方案，3D 先做**白模沙盘风格**。本文是第二版开发依据，在[第一版](网页前端第一版设计.md)基础上增量修改；第一版的数据约定、空状态、数值规则继续有效，视觉规范（第一版第 6 节）被本文第 3 节取代。

一套网页，三个入口，一份数据：

| 入口 | 地址 | 给谁看 | 设计 |
|---|---|---|---|
| 介绍页 | `/#/` | 评委、答辩开场 | 叙事式长页（参考 sondaven），首屏 3D 沙盘，滚动推镜头 |
| 孪生大屏 | `/#/twin` | 舞台常驻大屏 | 全屏 3D 沙盘，房间状态实时动作，可点房间看读数 |
| 管理页 | `/#/rooms`、`/#/rooms/:id`、`/#/camera` | 平板、手机日常管理 | 第一版三页结构不变，换成统一视觉，不上 3D |

三个入口都只用现有接口（`/api/rooms` + `/api/rooms/stream` + `/api/cv/stream`），后端不改。3D 只展示接口里真有的字段，不画人数、告警、今日电量、通断按钮。

## 2. 路由与布局

| 地址 | 页面 | 布局 |
|---|---|---|
| `/#/` | `IntroPage` | 无导航，全宽 |
| `/#/twin` | `TwinPage` | 无导航，全屏 |
| `/#/rooms` 等 | 第一版三页 | 原侧栏 / 底栏导航 |

- 路由用 `meta: { bare: true }` 标记无导航页，`App.vue` 据此决定是否渲染侧栏和底栏。未知路径改为跳转 `/`。
- 侧栏导航：品牌名（点击回介绍页）、客房用电、视频监控、孪生大屏。手机底栏仍是客房用电、视频监控两项，孪生大屏不进手机导航。
- `connect()` 仍在 `App.vue` 里调一次，三个入口共用同一条 SSE；`Home` 键切 mock 全站有效，介绍页与大屏一样显示「演示数据」角标。

## 3. 视觉语言（三个入口统一）

基调：宁波景区民宿的「纸与木」，白模沙盘像建筑事务所的模型桌；用电用一种暖琥珀色表达，越耗电越亮。

| 令牌 | 浅色（管理页、介绍页） | 深色（孪生大屏、介绍页孪生段） |
|---|---|---|
| `--bg` 页面底 | `#F5F2EC` 暖纸 | `#14161A` 夜 |
| `--card` 卡片 | `#FFFFFF` | `#1E2127` |
| `--text` / `--muted` | `#1F1D1A` / `#5E5A53` | `#EDEAE4` / `#A29D94` |
| `--border` | `#E4DED4` | `#2E323A` |
| `--power` 用电琥珀 | `#B45309`（文字）/ `#F59E0B`（发光） | `#FBBF24` |
| `--online` 在线、通电 | `#3F6B4E` 苔绿 | `#7FB08E` |
| `--offline` 离线、断开 | `#8A857C` | `#5B5F66` |
| `--warn` 数据中断 | `#92400E` / `#FFFBEB` | `#FBBF24` / `#3A2A10` |

- 颜色只有两个语义：琥珀 = 在用电，苔绿 = 在线。不再用第一版的蓝色主色；导航选中用 `--text` 加粗 + 左侧 3px 琥珀条。
- 字体：标题 `"Noto Serif SC", "Songti SC", serif`（介绍页大标题、页标题），正文与数字用系统无衬线 + `font-variant-numeric: tabular-nums`。Noto Serif SC 从 Google Fonts 只取标题用到的字重 600；现场断网时回退系统宋体，不影响布局。
- 介绍页字号：开篇大标题 `clamp(40px, 7vw, 96px)`，章节标题 `clamp(28px, 4vw, 48px)`，正文 18px，行高 1.7。管理页沿用第一版字号表。
- 圆角 12px，卡片 1px 边框无阴影；介绍页章节之间留白 `clamp(96px, 16vh, 200px)`。
- 动效：介绍页允许滚动显现与镜头运动；管理页读数仍然直接替换，不做跳字动画。`prefers-reduced-motion` 下介绍页关闭视差与镜头运动，3D 改为静止视角。

## 4. 3D 白模沙盘

### 技术选型

- 直接用 `three`（固定版本）写，不引 TresJS：Vue 只负责挂 canvas 和传 `rooms`，少一层封装更好读。
- 镜头动画与滚动用 `gsap` + `ScrollTrigger`（固定版本），只用在介绍页。
- 不导入外部模型文件，全部用 `BoxGeometry` 等基础几何程序化生成，不依赖 Blender。
- 渲染：`MeshStandardMaterial` 全哑光白 / 暖灰 + 轻量 `RoomEnvironment` 环境光；一盏暖色主光投影 + 天光补暗部；后处理 `GTAOPass` 环境光遮蔽（白模的"模型照"质感主要靠它）+ 多重采样抗锯齿；方块件带一圈细描边（`EdgesGeometry`），像板材切出来的。
- 大屏背景是深色展厅（`#14161A`），沙盘放在深色木框模型桌上，四角压暗角。

### 场景构成

用户已确认：不拘泥于原草图，按**江南合院式民宿**做白模。

```text
                 后山（等高线纸板叠层，台边切齐，山上几棵松）
        ┌───────── 马头墙 ─── 北排客房（门朝南）─── 马头墙 ─────────┐
        │                      回廊（细柱 + 檐枋）                    │
 [配电板]═院门═           天井：石板地、方池、桂花、景石              院墙
        │                      回廊（细柱 + 檐枋）                    │
        └───────── 马头墙 ─── 南排客房（门朝北）─── 马头墙 ─────────┘
   步道 ─ 石桥 ─────────────── 溪 ───────────────────────────────
   模型桌：深色木框嵌一块白板，散落球形模型树与锥形松
```

- 客房按 `id` 自然顺序排在天井南北两侧：每进天井最多 8 间（北排 4、南排 4，前一半北排），再多就往东再接一进，两进之间留一条弄、院墙开门相通；房间数变化时重建，不写死 6 间。
- 每排客房坐在台基上，天井一侧是回廊（细柱 + 檐枋），两端是三级阶梯马头墙；屋顶揭掉，只用淡色细线画出屋脊、檐口和椽子的轮廓（建筑模型里"揭顶"的表达）。
- 墙剖到窗台高（约 1.1 m），从斜上方直接看进室内：后墙中段压低成窗台，前墙开门洞；室内有床、床头柜、书桌椅、卫生间隔墙与洁具，让人一眼认出是客房。
- 电器按实体生成（名称或 ID 含「照明 / 灯 / light」→ 床头台灯；「空调 / ac」→ 侧墙壁挂空调；「插座 / socket」→ 墙插；其它 → 门边小方块）。同一电器的开关和电表（如 `light` 与 `light-meter`）只画一件；只用于选模型外形，不据此配对电表和开关（与第一版约定一致）。
- 房名用 `CanvasTexture` 贴在每间房门边的地面上，统一朝南摆，从主机位看是正的；长名截断加省略号。
- 配电网孔板立在西院门外：上排每房一只电能表、中间导轨上一排断路器、下面一块 ESP32。每房一根线管从板顶出线，翻过院门，沿回廊檐枋并排走，到门边垂落到前墙上。
- 景观：北面等高线叠层后山、南面一条溪加平板石桥、桥头步道通院门并岔到配电板、固定种子撒树（避开房子、溪、步道），只作氛围，不承载数据。
- 主机位从西南斜上方俯视（俯角约 50°，窄视角 30°），镜头按台面大小和屏幕横竖自动退到刚好装下。

### 数据到画面的映射

每秒收到快照后只改材质参数和少量物体可见性，不重建场景。所有映射写在一个 `applyRooms(rooms)` 函数里。

| 数据 | 画面 | 说明 |
|---|---|---|
| `online === false` | 房间墙体变暗灰、家具半透明，地面房名后加「离线」 | 读数是旧值，不发光、不流动 |
| 房间 `power`（在线） | 房间地面泛琥珀光：`emissiveIntensity = min(power / 2000, 1)` | 0 W 时纯白；2000 W 封顶 |
| 开关 `state === true` | 对应家具亮起：台灯灯罩发暖光 + 一盏小点光源；空调出风口细条、插座指示点、其它小方块顶上的指示点亮苔绿 | `false` 熄灭；缺失保持白模不亮 |
| 房间 `power > 0`（在线） | 配电板到该房间的线管上有琥珀光点流向房间，流速随功率 | 沿线管曲线移动的少量小球；离线、断流停止并隐藏 |
| 没有实体 | 空房间，地面写「未上报实体」 | 与第一版空状态一致 |
| 数据断流（`status` 为 broken / unavailable） | 整个画布降饱和（CSS `grayscale`）、光点停止，左上角状态标签提示 | 不让画面"假装还在动" |

- 点光源总数有上限（每房最多 1 盏，场景最多 8 盏），建沙盘时一次建好、只改亮度（灯数变化会让所有材质重编译），超出的房只用自发光；视口 < 640px 不建点光源。
- 不做告警红闪、人形、门开关动画：接口里没有这些数据。

### 交互

- 鼠标 / 触摸拖动旋转，滚轮 / 双指缩放（`OrbitControls`，限制俯仰角 25°～70°、不能钻到地台下面）。
- 悬停房间：墙顶描一圈琥珀边，鼠标旁浮出名牌（房名 + 功率）。
- 点击房间：镜头 0.8s 飞到房间斜上方，右侧滑出读数面板（复用第一版详情页的电表、开关卡），面板底部「查看详情 →」跳 `/#/rooms/:id`。再点空白处或 Esc 返回全景。
- 无人操作 30 秒后，镜头缓慢绕场景自转（大屏常驻用）；任何输入立即停止。

### 性能与降级

- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`；视口 < 640px 关闭阴影和点光源。
- 页面不可见（`document.hidden`）或 canvas 离开视口时暂停渲染循环。
- 离开页面时 `dispose()` 几何体、材质、渲染器，移除事件监听。
- WebGL 不可用时，3D 位置显示一张同构图的静态 SVG 平面图（房间方块 + 在线 / 功率颜色），保证介绍页与大屏仍可用。
- `three` 与 `gsap` 只在介绍页和大屏里用动态 `import()` 加载，管理页包体不受影响。

## 5. 介绍页 `/#/`

叙事式长页，七段。3D 画布 `position: sticky` 固定在视口里，文字层在上面滚动；每段对应一个镜头机位，`ScrollTrigger` 把滚动进度映射到镜头位置和场景状态。

| # | 段落 | 文字 | 画面 / 镜头 |
|---|---|---|---|
| 0 | 开篇 | 项目名（宋体大字）+ 一句话「让老旧民宿不大改线路，就能用上看得见、管得住、算得清的用电系统」+ 「向下滚动」 | 远景俯视整个沙盘，缓慢自转，房间暗着 |
| 1 | 痛点 | 三条：设施难改善 / 客人走了忘断电 / 用电说不清。每条一个大号序号 + 一句话 | 镜头压低，房间依次亮起空调、灯（mock 式演出：这一段用固定状态，不用实时数据），线路光点乱流 |
| 2 | 外挂集成式改造 | 「不动原有配电箱，外挂计量与通断模块」；三个部件名牌：RS485 电能表 / 可控断路器 / ESP32 | 镜头推到配电网孔板，三个部件依次高亮并拉出引线标注 |
| 3 | 实时数据 | 「以下是此刻的真实读数」+ 嵌入三张汇总卡（系统时间 / 当前总功率 / 累计电量）+ 一排房卡 | 镜头拉回全景，**场景切回实时数据**；背景转深色，琥珀光更显眼 |
| 4 | 人员感知 | 「摄像头判定线识别进出」+ 嵌入 `<img src="/api/cv/stream">` 小窗 | 3D 淡出，画面小窗居中；离开本段即移除 `img`，断开流 |
| 5 | 多端 | 「平板、手机、电脑一套网页」；三台设备轮廓里放管理页截图 | 静态图，不放 3D |
| 6 | 结尾 | 两个入口按钮：「进入管理平台 →」`/#/rooms`、「打开孪生大屏 →」`/#/twin` | 回到开篇机位，房间全部按实时数据亮着 |

- 第 1、2 段的演出状态写死在 `IntroPage` 里，明确是"讲故事用"；第 3 段起只用真实 `rooms`。第 3 段标题旁按 `status` 显示数据状态标签，mock 时显示「演示数据」。
- 文字显现：每段标题和正文进入视口时自下而上淡入（`opacity` + `translateY 24px`，0.6s），只用 `IntersectionObserver` + CSS class，不给每个字拆 span。
- 介绍页的养老关怀、可推广性等内容属于讲解词，等业务逻辑落地后再加段落，不提前画功能。
- 手机（< 640px）：3D 画布改为每段顶部一块 16:10 静态机位（同一场景，滚到该段时才切镜头，不做连续滚动绑定），避免滚动卡顿。

## 6. 孪生大屏 `/#/twin`

```text
┌──────────────────────────────────────────────────────────────┐
│ 民宿智能用电管理平台               14:23:07   ● 数据已连接   │
│                                                              │
│                                                  ┌─────────┐ │
│                 [ 全屏 3D 沙盘 ]                 │ 301 房  │ │
│                                                  │ 955 W   │ │
│                                                  │ 电表 / 开关│ │
│                                                  └─────────┘ │
│ 当前总功率 1.23 kW     累计电量 215.40 kWh       ← 管理平台  │

```

- 深色主题，画布铺满视口；四角放浮层，浮层半透明深底、不挡中心。
- 左上：项目名（宋体）；右上：系统时间 + 数据状态。左下：当前总功率、累计电量（口径同第一版第 3 节）。右下：「← 管理平台」链接。
- 右侧读数面板只在点击房间后出现（见第 4 节交互）。
- 按 `F` 或双击空白进入浏览器全屏；无人操作 30 秒自动绕转。
- 目标设备是演示电脑 + 外接大屏 / 投影；平板能用，手机不做专门适配（导航里也不放入口）。

## 7. 管理页换肤

结构、交互、数据规则全部沿用第一版，只做三件事：

1. `styles.css` 的 `:root` 换成第 3 节浅色令牌；第一版的 `--primary` 蓝改为第 3 节的选中样式与琥珀色。
2. 页标题、侧栏品牌名换宋体；房卡功率数字用 `--power` 琥珀色（0 W 与离线时用 `--muted`）。
3. 侧栏加「孪生大屏」入口，品牌名链接到 `/`。

不加 3D、不加动效、不改组件拆分。

## 8. 文件划分

```text
web2/src/
  twin/
    sandbox.ts      白模沙盘：按 rooms 程序化建合院、客房家具、配电板与线管、台面景观；layoutKey 判断是否需要重建；disposeSandbox
    scene.ts        渲染器、灯光、后处理、OrbitControls、镜头取景；applyRooms 数据映射；dispose
    TwinCanvas.vue  挂 canvas，watch(rooms, status) → applyRooms
    FloorPlan.vue   WebGL 不可用时的静态 SVG 平面图
  pages/
    IntroPage.vue   介绍页（gsap 只在这里）
    TwinPage.vue    孪生大屏（路由懒加载，管理页包体不含 three）
  components/
    RoomPanel.vue   房间读数面板：从 RoomDetailPage 抽出电表 / 开关卡，详情页与大屏共用
```

- three 代码只在 `twin/` 里：`sandbox.ts` 管"长什么样"，`scene.ts` 管"怎么渲染、怎么随数据动"。
- `scene.ts` 只暴露 `createScene(canvas)`，返回对象按步骤逐步加方法：第 3、4 步 `{ applyRooms, dispose }`，第 5 步加 `flyTo / flyHome` 与点选回调，第 7 步加 `setCamera`；不引入状态库或事件总线。
- 新依赖：`three`、`@types/three`、`gsap`，写死精确版本，用 `bun add` 安装（`gsap` 到第 7 步再装）。

## 10. 并行开发与隔离

第二版在新目录 `web2/` 开发，**第一版 `web/` 不动**，两版可同时运行、连同一个后端，第一版随时可演示。

- `web2/` 由 `web/` 整份复制而来，包名 `web2`，加进根 `package.json` 的 workspaces；开发端口 5174，`/api` 同样代理到 `127.0.0.1:8080`。
- `data.ts` / `api.ts` / `mock.ts` 两边各一份；第一版若有修复，手动同步到 `web2/`。
- 不用 git 分支：第二版要改 `styles.css`、`App.vue`、`router.ts`，分支合并必冲突，也不能两版同跑。
- 第二版验收通过后：删除 `web/`，`web2/` 改名 `web/`，包名、端口改回，workspaces 去掉 `web2`。

第二版内部：先由一人完成**地基**（第 1、2 步的路由、布局、令牌，抽 `RoomPanel`，并把 `scene.ts` 入口定死为 `createScene(canvas)`），然后三条线并行，各改各的文件：

| 线 | 内容 | 动的文件 |
|---|---|---|
| A 3D 场景 | 第 3、4 步 | `twin/sandbox.ts`、`twin/scene.ts` |
| B 介绍页文字层 | 第 6 步 | `pages/IntroPage.vue` |
| C 管理页换肤 | 第 1 步的视觉部分 | `styles.css`、管理页与 `components/` |

汇合：第 5 步孪生大屏（等 A）→ 第 7 步介绍页接 3D（等 A、B）→ 第 8 步收尾。
