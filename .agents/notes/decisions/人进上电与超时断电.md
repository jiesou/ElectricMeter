# 人进上电与超时断电

## 落点

- 业务在 `server/core/AutoOffOn.ts`，`server/index.ts` 启动时 `startAutoOffOn()`，1s 一拍。
- 不新增协议、接口、表：下的是既有的 `pub_action_switch`，开关状态仍只由设备 `ack_action_switch` 回写。
- 判据读 `hub.devices` 里那间房当前的 `netCount`，不订阅、不加钩子。

## 判据

- 只看房间里 `people-counter` 的 `netCount`（大屏 / 摄像头替这间房报）。
- 0 → >0：该房全部 `switch` 合闸。
- >0 → 0：开始计时，5s 后仍是 0 就把全部 `switch` 分闸；5s 内回到 >0 就撤销。
- 只认跳变：人还在房里手动关掉的回路不会被开回去。
- 空房断过一次就停手（期限记为 `Infinity`），空房里再手动合闸不再断，直到下一轮人进人出。
- 跳过 `bigscreen`（`isRoom`）与没有人数的房；服务器启动后第一次看到的状态只记录、不动作。
- 已经处于目标状态的回路不发指令。

## 时序

- 1s 巡检，「5s」实际落在 5~6s。
- 期限标记只在内存，服务器重启后空房重新从 5s 算起。

## 验收

`server/core/AutoOffOn.test.ts` 用 `check(ts)` 传时间把 5s 快进，覆盖：人进全房合闸、人在房内不反复下发、人出满 5s 才分闸、5s 内回来撤销、空房只断一次。
