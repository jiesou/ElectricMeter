# 统计与入住记录

## 数据

- 新表 `EnergyUsageTime`：`device_id` / `start_ts` / `end_ts`（在住时为 null），主键 `(device_id, start_ts)`，外键指向 `Device`、`onDelete: Cascade`。**一次入住就是一段起止时间**，用了多少电一律现查（做差口径见[历史记录与统计](历史记录与统计.md)），不存账单数字。
- 房名不抄快照，要显示就从 `Device` 关系里取。
- 在住判定：`end_ts` 为空。服务器内存里维护在住表，启动从库读。

## 接口

| 接口 | 作用 |
|---|---|
| `POST /api/clock/next-day` | 服务器时间 +86400 秒 |
| `POST /api/rooms/:device_id/checkin` | 开一段入住（`start_ts` = 现在） |
| `POST /api/rooms/:device_id/checkout` | 填上 `end_ts` |
| `GET /api/stats` | 一次给全，见下 |

`GET /api/rooms` 快照里每间房多一个 `occupied`：这间房现在有没有人住。

`GET /api/stats` 返回：

- `now`：服务器时间。
- `rooms`：每间房 `{ id, name, occupied, start_ts?, kwh, days: [{ day, kwh }], hours: [{ hour, kwh }], devices: [{ id, name, kwh }] }`。在住就是这段，空房就是它刚退的那段。
- `stays`：客户用电情况记录表，每行 `{ device_id, room, start_ts, end_ts, days, kwh, top, percent }`。
- `avg_hours`：历史入住平均的 24 小时分布，给本次入住当对比的幽灵柱。

口径：

- 本次入住总用电 = 每块电表「退房时刻（在住就是现在）的值 − 入住时刻的值」求和。
- 按天：逐日 0 点取值做差；24 小时分布：逐小时取值做差，同一入住里同一个小时累加。
- 设备构成：按电表分别做差，降序。
- 百分位 `percent` = 这张账单的总用电超过了多少比例的历史入住（含演示样本）。

## 演示样本

- 代码放 `server/simulator/stays.ts`，跟 `esp32.ts` / `bigscreen.ts` 一样属于演示数据侧；server 起来后定期看一眼，哪间房账本还是空的就给它把过去铺出来，铺过就不再铺。
- 就是 `EntityHistory` 行，形状与真实数据一样，只是 `powerW` 空着、`energyKwh` 按作息曲线（晚上多、凌晨少）单调递增地铺；再按天划出若干次入住写进 `EnergyUsageTime`。
- 用的都是已经接入的真实房间和它的真实电表：不造房间、不造实体、不编 id。
- **采样频率比真实低**：真实是报文频率（约 3.4 Hz），样本一分钟一行 —— 账本存的是累计电量，做差不看密度，密度只影响曲线的细腻程度。18 块表一天 2.6 万行，铺 30 天不到 80 万行。
- 铺完把内存里的累计值接到样本最后一行，实时数据接着往下涨。
- 直接批量插入，不走 Prisma 逐条。
- 铺多久由 `SEED_DAYS` 常量控制。

## 统计页

- 顶部一行：今天（服务器时间里的当地日期）。
- 在住 / 空房列表：一行一间房，房名、「在住 · 第 N 天」或「空房」、已用 kWh、日均，行尾「办理入住」或「办理退房」。
- 选中一间看本次入住：按天柱状图 + 24 小时分布（与历史平均叠一层对比）+ 设备构成横条。
- 客户用电情况记录表：房号、起止、天数、总 kWh、日均、主要设备、超过百分之多少的客人。
- 页面每 2 秒拉一次 `GET /api/stats`。
- 形态与配色见[网页前端设计](网页前端设计.md)。

## 角色切换

- 页头右侧三档：**访客**（默认）/ **保洁** / **管理**。运行期状态，不持久化，刷新回访客。
- 客房管理页的电闸（单个闸与整房总闸）按角色放开：

| 角色 | 单个闸 / 整房总闸 |
|---|---|
| 访客 | 一律不可点 |
| 保洁 | 只有空房（`occupied` 为假）可点 |
| 管理 | 都能点 |

- 不可点的闸灰掉，点了没反应。
- 角色只做界面上的放行，服务器不做鉴权（原型不做登录）。
