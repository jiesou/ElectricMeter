# 网页前端第一版设计

## 1. 定论与演示目标

本方案按用户要求确定为网页第一版开发依据；页面已在 `web/` 按此实现。

面向民宿管理人员，完成一条可演示的路径：**看全部客房用电 → 进入一间房看电表和开关 → 查看带检测框的摄像头画面**。同一套网页适配电脑、平板、手机。

第一版做三个页面：客房总览、客房详情、视频监控。一级导航只有「客房用电」「视频监控」，客房详情属于客房用电。

第一版的客房管理范围是查看、搜索、筛选和进入详情；不做新增、改名、删除、入住登记。一个设备暂对应一间客房，直接使用现有 `/api/rooms` 聚合结果，不新增房间模型或映射表。

| 第一版包含 | 留待后续，不在第一版放空页面或占位按钮 |
|---|---|
| 客房状态、功率、电量、实体读数与开关状态 | 远程通断、批量通断、动作结果反馈 |
| 每秒更新的客房快照 | 今日用电、历史曲线、节能率、电费统计 |
| 单路带框视频展示、重新加载、全屏 | 多摄像头选择、房间与摄像头绑定、录像回放 |
| 多端布局、搜索筛选、必要空状态 | 人数数字、入住状态、告警中心、自动控制规则 |
| 独立mock演示与真实接口联调 | 登录权限、设置中心、3D 数字孪生 |

现有视频流不包含结构化人数数据；即使画面里有检测框，也不能据此生成房内人数。开关使用只读状态标签，不画可点击的开关控件。

## 2. 导航与整体布局

采用 Vue 3 + TypeScript + Vite + Vue Router，使用普通 CSS。依赖安装、开发、构建一律用 Bun。第一版不引入组件库、全局状态库或图表库。

使用 Hash 路由，静态服务器无需配置路由回退：

| 地址 | 页面 | 入口 |
|---|---|---|
| `/#/rooms` | 客房总览 | 默认首页、客房用电导航 |
| `/#/rooms/:device_id` | 客房详情 | 客房卡片 |
| `/#/camera` | 视频监控 | 视频监控导航 |

默认路径和未知路径跳转客房总览；未知客房保留详情页，展示「未找到该客房」与返回入口。设备 ID 作为路由参数时编码，不从房间名称推导 ID。

## 3. 客房总览

### 内容顺序

1. 页头：「客房用电」，副标题「查看各客房当前用电与设备状态」，右侧展示数据更新状态。
2. 三张汇总卡：「客房数」「在线设备」「在线客房总功率」。电脑三列，手机前两张各半宽，功率卡独占下一行。
3. 工具栏：按客房名或设备 ID 搜索；「全部／在线／离线」单选筛选；显示当前匹配数量。
4. 客房卡片网格，按 `id` 自然顺序排列，读数更新时不重新按功率排序。

汇总始终统计全部客房，不随搜索筛选变化。在线数直接统计 `online === true`；总功率只合计在线房间的 `power`，离线房间保留的旧读数不参与。没有在线房间时总功率显示 `—`；在线房间报告零功率时显示 `0 W`。

### 房卡

- 第一行：客房名称、在线／离线文字标签。名称为空时显示设备 ID；长名称允许换行。
- 第二行：当前功率为最大数字，单位 W。
- 第三行：累计电量，单位 kWh。
- 底部：电表数量、开关数量和进入详情箭头。数量按实体 `type` 分别统计，不能把两个实体算成两条物理回路。
- 整张卡是进入详情的链接；悬停仅改变边框和背景，键盘可聚焦、回车打开。
- 离线卡保留数值，标题改为「最后功率」「最后累计电量」，明确是旧值。
- 在线但没有任何电表时，功率和电量展示 `—` 与「未上报电表」；不能用接口聚合出的默认零表示实际零用电。

搜索在本地对名称和 ID 做包含匹配，不发新请求，不加分页。进入详情再返回时，在当前页面会话内保留搜索和筛选条件。

## 4. 客房详情

```text
┌───────────────────────────────────────────────────────┐
│ ← 返回客房列表                         数据更新状态   │
│ 301 房  [在线]                          esp-301       │
│                                                       │
│ [当前功率 955 W]          [累计电量 66.70 kWh]          │
│                                                       │
│ 电表读数                                              │
│ [照明功率 55 W] [插座功率 0 W] [空调功率 900 W]        │
│ [累计电量…   ] [累计电量…   ] [累计电量…      ]        │
│                                                       │
│ 开关状态                                              │
│ [照明  通电]    [插座  断开]    [空调  通电]           │
└───────────────────────────────────────────────────────┘
```

- 页头显示返回链接、房间名称、设备 ID、设备状态；不额外请求 IP、心跳信息来填充页面。
- 摘要显示房间功率与累计电量，含义和总览一致。电脑两列，手机两列放不下时垂直排列。
- 「电表读数」按 `type === 'meter'` 展示，每卡包含名称、`powerW`、`energyKwh` 和实体 ID。电脑最多三列，平板两列，手机一列。
- 「开关状态」按 `type === 'switch'` 展示，每卡包含名称、实体 ID 和「通电／断开」标签；`state` 缺失时显示「未上报」。
- 电表和开关分别排列。不根据 `-meter` 后缀、名称相似或数组位置猜测配对，现有模型没有正式的回路关联字段。
- 状态使用文字加颜色；没有操作按钮、确认弹窗、假通断反馈。
- 离线时在摘要下方展示「设备离线，以下为最后上报数据」，开关标签写「最后状态：通电／断开」。
- 没有实体显示「该客房尚未上报实体」；某一类为空时该分区显示「暂无电表／暂无开关」。
- 接口尚未返回时不提前判断客房不存在；收到快照后才判断。

数值显示规则：功率统一 W、最多一位小数；电量统一 kWh、两位小数。缺失读数显示 `—`，明确的 `0` 和 `false` 必须正常显示。

电量标题只能使用「累计电量」：当前读数可能随下位机重启归零，不能解释为今日用电、历史总消耗或结算依据。

## 5. 视频监控

第一版只有一个摄像头流，全局查看，不与具体客房绑定。

- 页头：「视频监控」，副标题「查看人体检测与跨线判定画面」。
- 主区域：16:9 黑底画面容器，图像 `object-fit: contain`，保留完整画面，不能裁掉检测框与判定线。
- 电脑：画面与说明栏约 3:1；宽度小于 1024px 时说明栏移到画面下方。
- 说明栏只说明实际可见的内容：「绿色框：检测到的人体」「判定线：进出方向判定参考」。不展示人数、准确率、帧率或摄像头在线指示灯。
- 画面下方提供「重新加载」「全屏查看」。重新加载只重建当前图像请求；全屏使用浏览器 Fullscreen API，不支持时隐藏该按钮。
- 直接以 `<img src="/api/cv/stream">` 接收 MJPEG，不接入播放器或转码服务，不在网页重复画检测框。
- 页面离开时移除图像并断开流，返回时重新请求。

初始显示「正在连接画面」。目标演示浏览器能可靠报告图像首次加载时再隐藏提示；在真实 MJPEG 联调中检查该行为，不能把普通图片的完整下载作为流式加载前提。明确加载失败时显示「画面加载失败」和重新加载入口。

现有接口没有首帧超时状态、采集时间或摄像头心跳，而且发送端停止后服务器仍可能重复最后一帧。因此第一版只承诺展示收到的画面，不声称能识别摄像头离线或画面停滞。演示前必须确认图传进程运行、画面实际变化；视频无信号不应影响客房页面。

## 6. 视觉规范

采用浅色、简洁的管理界面，以房间名称和读数为重点。首版只做一种主题。

| 项目 | 定值 |
|---|---|
| 页面背景 / 卡片背景 | `#F8FAFC` / `#FFFFFF` |
| 主文字 / 次要文字 | `#0F172A` / `#475569` |
| 主色 / 选中浅底 | `#1D4ED8` / `#EFF6FF` |
| 在线、通电 | 深绿 `#15803D`，浅绿底 `#F0FDF4` |
| 离线、断开 | 灰色 `#475569`，浅灰底 `#F1F5F9` |
| 数据连接中断提示 | 深棕 `#92400E`，浅黄底 `#FFFBEB` |
| 卡片边框 / 圆角 | `#E2E8F0`，1px / 12px |
| 间距 | 8、12、16、24、32px；卡片间距 16px |
| 字体 | 系统字体，中文优先苹方、微软雅黑，无外网字体依赖 |
| 字号 | 页标题 28px（手机 24px），关键读数 32px，正文 16px，辅助信息 14px |

数字使用等宽数字样式，减少每秒更新时的跳动。读数直接替换，不做滚动数字、闪烁、脉冲或仪表盘动画。卡片不使用大面积渐变、毛玻璃或重阴影。

按钮和触控区域至少 44×44px，普通文字对比度至少 4.5:1。图标用同一套简洁 SVG，并保留文字或无障碍名称；焦点清晰可见，交互不依赖悬停。状态变化不反复播报整页读数，尊重减少动态效果设置。

## 7. 接口与数据更新约定

以下为规划时已核对的现有接口，第一版不要求后端增加业务接口。

| 用途 | 接口 | 返回与使用方式 |
|---|---|---|
| 初始房间数据 | `GET /api/rooms` | 返回客房数组 |
| 持续更新 | `GET /api/rooms/stream` | 立即一次、随后每秒一次的完整客房数组 |
| 视频画面 | `GET /api/cv/stream` | MJPEG，直接给图像元素 |

客房响应结构：

```ts
type Room = {
  id: string;
  name: string;
  online: boolean;
  power: number;
  energy: number;
  entities: Entity[];
};
```

`Entity` 引用 `shared/types.ts`，本地 `Room` 只描述 REST 响应，不改共享协议。实体身份使用「设备 ID + 实体 ID」；名称缺失时回退到 ID。

应用启动先请求一次 REST，成功或失败后都尝试连接 SSE；总览和详情共用同一份 `rooms` 数组、一条 EventSource，不重复订阅设备和实体流。SSE 使用默认 `message` 事件，解析 `event.data` 后直接替换整个数组，不做增量合并。先完成 REST 再建立 SSE，避免旧 REST 结果覆盖新快照。

| 数据状态 | 页面表现 |
|---|---|
| 尚无首次结果 | 固定高度的加载占位，避免空白闪动 |
| 收到 SSE 快照 | 页头显示「数据已连接」 |
| REST 成功、SSE 尚未收到快照 | 展示 REST 数据，标注「正在连接实时更新」 |
| SSE 中断 | 保留已有数据，标注「更新中断，显示上次数据」；由 EventSource 自动重连 |
| REST 失败且 SSE 也未取得数据 | 显示「暂时无法获取客房数据」；SSE 继续自动重连 |
| 成功返回空数组 | 显示「暂无客房，等待设备接入」 |
| 搜索无结果 | 显示「没有匹配的客房」，提供清空筛选 |

应用关闭时销毁 EventSource。切换页面不反复建立 SSE，不加消息队列、状态同步框架或轮询兜底。

`online` 直接使用服务端值，前端不补心跳超时判定。浏览器到服务器的数据连接状态与设备在线状态分别显示；数据断流时所有房间状态都只是最后快照。

`lastUpdate` 是实体字段最后上报时间，稳定读数未变化时也可能很久不变，不能用它判断设备离线。所有时间数据使用 number 秒级时间戳；首版不展示日期时钟、不新增格式化时间字段。

聚合接口会把缺失读数按零计算。存在电表但部分读数缺失时，房卡和汇总旁显示「读数未齐」，实体卡缺值仍为 `—`，不能把默认零当成实际测量。未知或缺失的实体类型不猜测，详情显示「存在未识别实体」。

## 8. 前后端错开开发

新增前端目录 `web/`，主要划分为 `App.vue`、三个页面、少量共享卡片、`api.ts`、`mock.ts` 和全局样式。只抽取实际重复的组件，不提前搭通用业务框架。

- `data.ts` 持有客房数据、连接状态与 mock 开关，`connect()` 按当前来源取数，页面直接引用；搜索和筛选仍由 `App.vue` 用 props 传给页面。`api.ts` 负责 REST、EventSource 的创建和关闭。
- `mock.ts` 返回相同的客房结构，每秒更新读数，用于独立开发；不搭额外 mock 服务器。
- 按 `Home` 键运行期切换mock，不用启动变量；默认连接真实接口，mock模式页头一直显示「演示数据」，真实接口失败时不自动切换mock。注入点与切换语义见 [Mock 模式](Mock模式.md)。
- mock准备 6 间房：正常在线、零功率在线、离线且有旧读数、暂无实体、实体较多、名称较长且部分读数缺失；覆盖不同数量的电表和开关。
- 视频页不参与mock，画面只能来自真实 MJPEG 链路，必须单独联调。
- 开发服务器代理 `/api` 到 Bun 后端 `http://127.0.0.1:8080`，前端只写相对 API 地址；代理目标用配置变量覆盖，不做用户设置页面。
- 开发端口固定为 5173，并监听局域网地址，手机和平板访问同一前端开发服务。SSE 与 MJPEG 代理必须保留流式传输。
- 提供计划命令：`bun install`、`bun run --cwd web dev`、`bun run --cwd web build`。

开发阶段只改 `web/` 及必要的根 workspace 注册、锁文件，不改 `shared/types.ts` 和后端业务。遇到接口变化集中修改 `api.ts`；远程控制等新功能另行确定接口，不预先写假地址。

## 9. 实施顺序与演示脚本

### 实施顺序

1. 建立前端工程与路由，用mock完成整体布局、总览和详情，先检查 360px 与 1440px。
2. 完成视频页、平板布局、搜索筛选与空状态，检查长名称、多实体和缺失读数。
3. 接入客房 REST + SSE，验证只建立一条连接、刷新及重连后数据继续更新。
4. 连接现有模拟器与图传，检查真实字段、MJPEG、手机和平板访问，形成可重复演示。

以上是网页实施顺序，不把后端长期规划纳入首版待办。

### 三分钟演示

| 顺序 | 操作 | 观众看到什么 |
|---|---|---|
| 1 | 打开客房总览 | 客房数、在线数、功率；房卡读数随模拟器上报变化 |
| 2 | 搜索并打开一间客房 | 对应电表的功率和累计电量、各开关当前状态 |
| 3 | 返回总览并筛选在线／离线 | 设备状态有文字区分，离线读数标为最后数据 |
| 4 | 打开视频监控 | 持续变化的标注画面，演示全屏查看 |
| 5 | 用手机打开同一网页 | 单列房卡、底部导航，仍能进入详情和看画面 |

演示前启动 Bun 服务、至少两个不同 `DEVICE_ID` 的现有模拟器，以及向服务端发送画面的 Slint 感知侧。设备名以接口实际返回为准，可能仍是 `esp-301`，不在前端擅自改成房号。离线场景通过正常关闭一个模拟器、确认服务端收到断开后展示；异常断网超时识别尚不在首版能力内。

mock用于页面独立演示；最终集成演示须走真实 REST、SSE、MJPEG 链路，并说明读数来自下位机模拟器、摄像头源可为测试视频。

## 10. 验收标准

- 三个页面可以互相到达，详情地址刷新仍可打开，未知客房有明确返回入口。
- 360×800、768×1024、1024×768、1440×900 下没有整页横向滚动、文字遮挡或底部导航盖住内容；实现后逐页截图自查。
- 总览搜索、筛选正确；详情实体种类、数量和读数与接口一致，`0`、`false`、缺失值、空数组能区分。
- 房卡保留稳定顺序；实际变化上报到服务端后，局域网正常环境下约两秒内可在网页看到更新。
- SSE 中断时保留旧值并出现提示；恢复后继续更新，没有重复订阅或自动换成mock。
- 离线值不计入在线客房总功率；没有电表与读数不齐有明确提示；不显示虚构的今日电量、人数和告警。
- 视频通过实际 MJPEG 接入，画面完整且会变化；重新加载有效，支持的浏览器可全屏，离开页面断开图像请求。
- 在演示电脑浏览器和实际手机浏览器检查 MJPEG 首帧、持续播放与重连；静态假图不替代该项验收。
- 正常按钮和链接可键盘操作，状态有文字说明，手机主要触控区域至少 44px。
- 前端类型检查、构建通过；mock模式无需启动后端即可演示客房页面。验收以构建、实际联调和截图为主，不额外搭大型测试体系。
